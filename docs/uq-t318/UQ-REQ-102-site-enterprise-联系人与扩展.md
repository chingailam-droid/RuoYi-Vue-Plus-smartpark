## 1. 锁死结论

1. 角色字典跟 S3：类型名 `uq_enterprise_contact_role`。五码 `LEGAL`（法人）、`FINANCE`（财务）、`IT`、`ADMIN`（行政）、`HR`。角色可空；非空只能是这五码。种子仍归 S3，本稿不写种子正文。
2. 联系人列表含启停列。启停为 `ACTIVE`（启用）/ `INACTIVE`（停用），规则与 MOD-102 R4 相同：编辑直改，无审批；停用不是删除。
3. 本切片不做联系人逻辑删除，不对齐成必做。验收 C7 标为「本切片不适用 / 延后」。
4. 本切片验收入口是企业档案列表（`UQ-SCR-SITE-ENT-01`）的行操作「联系人」，打开右侧抽屉（`UQ-SCR-SITE-ENT-03`）。独立路由或一级菜单可以保留，不作为本切片验收。

MOD-102 R4 已另卷收口：编辑锁定 `enterprise_id`；§8 Q1–Q5 已拍板。本稿只写需求与验收，不改那一卷。

## 3. 入口

`UQ-SCR-SITE-ENT-01` 须补行操作「联系人」。无 `site:enterprise:contact:list` 时按钮不出现，接口 403。

抽屉从该行打开，宽度与档案抽屉相同（650px）。标题为企业名称加「联系人」。信用代码、入驻状态只读，联系人接口不以入驻状态做门禁（MOD-102 §8 Q3）。

企业不存在、跨租户或已删除：统一为一条业务错误，抽屉文案「企业不存在或无权」。不把这三种情况分成不同文案，也不当成空列表。

企业存在且当前用户可访问、但没有联系人：空列表，可以新建。

独立路由 `/uq/site/enterprise/contact` 与对应菜单若已在页面草案里，可以留。本切片冒烟与验收不从该路由进入。

## 4. 数据项

表 `uq_enterprise_contact`。无物理外键。列的类型与默认以库卷为准；下面是本切片要遵守的规则。`biz_id`、`ext_json` 若库表保留，不进新建、编辑、查看表单（MOD-102 §8 Q4）。

| 逻辑名 | 列名 | 必填 | 规则 |
| --- | --- | --- | --- |
| 主键 | `id` | 是 | 与平台主键惯例一致 |
| 租户 | `tenant_id` | 是 | 与所属企业相同 |
| 所属企业 | `enterprise_id` | 是 | 指向 `uq_enterprise.id`。新建时企业须存在，表单可选，从 ENT-01 某行进入时默认该企业。编辑只读；请求中的值与库内不一致则拒绝且不落库 |
| 姓名 | `contact_name` | 是 | ≤64，去掉首尾空格后非空 |
| 电话 | `contact_phone` | 否 | ≤32。无唯一约束，同企可重复。非空时做格式软校验（数字、`+`、`-`、空格），不作为库约束 |
| 角色 | `contact_role` | 否 | 空或五码之一。非法值拒绝 |
| 启停 | `contact_status` | 是 | `ACTIVE` / `INACTIVE`。新建默认 `ACTIVE` |
| 主联系人 | `is_primary` | 是 | `1` / `0`，新建默认 `0`。同一企业未删除行至多一条为 `1`，应用层保证 |
| 备注 | `remark` | 否 | ≤512 |
| 审计列 | 框架惯例 | 是 | 与平台一致 |
| 逻辑删除标志 | `del_flag` | 框架可有 | 本切片不提供把该标志改为已删除的操作 |

不建列：邮箱、证件号、即时通讯号、部门、排序号、职务自由文本。

### 4.1 回写主档扁化列

主档仍只有 `contact_name`、`contact_phone`，不增删列。联系人保存时由服务回写，页面不另提交主档字段。

| 动作 | 扁化列 |
| --- | --- |
| 将某行设为 `is_primary=1` | 同企其他未删除行的主标记改为 `0`；扁化姓名、电话改写成该行（电话空则扁化电话为空） |
| 主联系人行修改姓名或电话 | 扁化列跟随该行 |
| 更换主联系人 | 扁化列改指向新的主行 |
| 取消主标记，或停用当前主联系人 | 保留快照，不自动清空（MOD-102 §8 Q2） |

取消或停用主联系人后的快照，与「后切片若启用删除、删尽主联系人则主档置空」不是同一条规则。后者是延后的 C7，本切片不实现、不冒烟。

### 4.2 档案表单并存

ENT-01 新建/编辑仍保留主联系人姓名、电话，不增删字段。

- 该企业没有 `is_primary=1` 的未删除联系人：档案表单只改主档。
- 已有该主联系人行：保存档案时，姓名、电话以本次表单为准回写该行。角色、启停、主标记不动。同一事务。
- 档案表单不自动插入联系人行。

## 5. 操作路径

### 5.1 打开

1. 用户在 `/uq/site/enterprise/list` 点击某行「联系人」。
2. 前端带该行 `enterpriseId` 请求联系人分页。
3. 企业不存在、跨租户或已删除：抽屉只显示「企业不存在或无权」。
4. 无列表权限：不出现按钮；直接请求为 403，不使用上一条文案。
5. 企业有效且无联系人：空列表。

### 5.2 子列表

- 分页，页大小跟随平台默认。
- 排序：主联系人在前，其余按修改时间倒序；修改时间相同则按主键倒序。
- 列：姓名、电话、角色、是否主联系人、启停、更新时间、操作（查看 / 编辑）。
- 无删除操作。
- 备注在查看态，不占主列。
- 启停列文案为启用 / 停用。停用行仍出现在列表中，可再编辑为启用。

### 5.3 新建

1. 抽屉内打开空表单。所属企业默认当前行，可以改选其他本租户未删除企业。姓名必填。角色默认空。启停默认启用。主联系人默认否。
2. 勾选主联系人时，同企原主联系人改为非主，扁化列改写成新行。同一事务。
3. 两人同时把不同行设为主联系人时，不得留下两条未删除的主联系人；失败返回明确文案。
4. 成功后：所属企业仍是当前企业则留在抽屉并刷新；改选了其他企业则当前子列表不显示该行。

### 5.4 编辑

可改姓名、电话、角色、启停、主标记、备注。所属企业只读。请求中的 `enterprise_id` 与库内不一致时拒绝，不落库。本切片不能换企。

取消主标记允许保存。扁化列保留取消前的姓名、电话（Q2）。当前若需要主档改指向别人，须把另一行设为主联系人。

改为新的主联系人时，原主联系人降为非主，扁化列指向新行。同一事务。

### 5.5 查看

只读。所属企业不可改。字段与库一致。

### 5.6 启停

在编辑中把 `ACTIVE` 与 `INACTIVE` 互改，无审批，不删行。停用的是主联系人时，扁化列保留快照（Q2）。停用后仍可查询、可再启用。

### 5.7 删除

本切片不做。不提供逻辑删除、不挂删除按钮、不启用 `site:enterprise:contact:remove`。

若后切片启用删除，另行写明为非默认能力，并单测 C7：删尽主联系人后主档姓名、电话置空。该测不并入本切片冒烟，也不得拿来代替 Q2（取消或停用主联系人 → 扁化列保留快照）。

## 6. 接口与权限

前缀 `/uq/site/enterprise`。响应包装与平台一致。不引入支付类幂等键。本切片不提供删除接口。

| 方法 | 路径 | 说明 | 权限 |
| --- | --- | --- | --- |
| GET | `/uq/site/enterprise/contact/list` | `enterpriseId` 必填，加分页。企业无效时返回统一业务错误，不返回空页冒充成功 | `site:enterprise:contact:list` |
| GET | `/uq/site/enterprise/contact/{id}` | 详情 | `site:enterprise:contact:query` |
| POST | `/uq/site/enterprise/contact` | 新建；body 含 `enterpriseId` | `site:enterprise:contact:add` |
| PUT | `/uq/site/enterprise/contact` | 编辑；`enterpriseId` 与库内不一致则拒绝 | `site:enterprise:contact:edit` |

无权限为 403。主联系人冲突、角色非法、换企、企业无效，返回业务文案，不用 500 代替。企业无效的文案与抽屉一致，测试只认「企业不存在或无权」这一条。

菜单不新增本切片必达的一级目录。ENT-01 上增加按钮「联系人」。联系人查询、新增、修改随抽屉内操作授权。不挂删除。`menu_id` 仍归 S3 / `UQ-DB-091`，本稿不指定数字。

数据范围只做租户隔离。企业主档若以后补数据权限，联系人跟随 `enterprise_id`。
