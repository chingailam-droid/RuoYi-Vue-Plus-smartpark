## 1. 旁注的用途

园擎业务大纲原先按域罗列能力，首切片已经收成冻结稿 `UQ-REQ-101`（site-enterprise 最小档案 + 列表）。本稿不改那份冻结范围，只把大纲收成一条可执行的业务 REQ 顺序，并与库侧切片序对齐。

读法：

- **B 节点**是业务需求顺序。准出物是给运营人员用的能力，以及对应的 `UQ-REQ-*` 详规。
- **S 节点**是库与四类详设顺序（功能 / 页面 / 库 / 接口）。业务节点对齐它，库治理本身不单独立成业务需求。
- **门禁**是能力底座。只写它挡住哪条业务，不把底座全表写进业务清单。

`UQ-REQ-101` 的字段、接口和验收表以冻结稿为准。本稿只保留节点名、依赖和「编码 HOLD」。

## 2. 域能力（一条准出，避免重复）

| 域 | 业务准出 | 不吸收进早期节点的内容 |
| --- | --- | --- |
| 园企中心 | 先有可检索的企业主档，再维护多名联系人，并让列表上的联系人列与主联系人一致 | 合同权威、完整客户经营关系 |
| 物业中心 | 报修/投诉从受理到派单、处理、回访走完 | 与巡检、设备告警的自动建单 |
| 结算中心 | 费项、按企业出账、登记收缴 | 减免审批流、对账导出 |
| 运营中心 | 招商线索登记与阶段推进；成交后引用已有企业主键 | 合同索引（单独开卷，不塞进联系人切片） |
| 门户 | 工作台汇集已发生的待办与通知入口 | 替换或改写平台首页 |
| 资产 / 仓储 / 物流 | 主链路之后，各自一条台账最小闭环 | 并进园企或工单的首个闭环 |

跨域规则在每份详规里保持不变：业务数据默认租户隔离；关键写操作留审计；新表使用 `uq_` 前缀；业务 API 使用 `/uq/`；平台 `sys_*` 只插数据、不改结构；跨域只用逻辑 id，不建物理外键。与能力底座的事件联动，在引入该事件的那份详规里写幂等和失败处理，大纲不预写协议。
