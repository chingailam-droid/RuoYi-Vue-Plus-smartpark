> **测勿混用**：REQ-102 §7 C7（删尽主联系人→主档姓名/电话置空）≠ MOD-102 §8 Q2（取消/停用主→扁化保留快照不自动清空）。

## 1. 问题与结论

冻结稿把联系人收成企业主档上的姓名和电话，列表能展示，不能维护多名联系人，也不能在不直接改档案的情况下更换主联系人。

本切片补上独立联系人，并保证企业列表上的「联系人」列始终等于当前主联系人。企业主档的列集合、入驻状态、位置写法、信用代码规则保持冻结稿，不在本稿重列。

「扩展」在本切片的含义只有一件事：联系人从主档展示字段提升为子表，并写明与主档两个展示字段的回写。参考库序里企业域的其余实体（证照、账户、标签等）没有随 uploads 进入本仓，骨架正文也不在本仓。那些实体不进入本节数据项；升四类详设时若骨架已有列，另开对照，不反向扩大本 REQ。

## 2. 范围

| 能力 | 本切片 |
| --- | --- |
| 按企业维护多名联系人（新建、查看、编辑、逻辑删除、分页） | 必做 |
| 每家企业至多一名主联系人，并回写主档姓名、电话 | 必做 |
| 主档已有姓名、尚未有主联系人时，一次生成主联系人 | 必做 |
| 档案表单与主联系人行的姓名、电话保持一致 | 必做（规则见 §5.8） |
| 从企业列表进入联系人抽屉 | 必做 |
| 独立详情路由、独立联系人菜单页 | 可有，不作为验收条件 |
| 企业主档新列、合同、证照、开票、标签、导入导出 | 不做 |
| 物理删除、跨企业调拨联系人、企业人员自助修改 | 不做 |

使用人是已能维护企业档案的内部账号（租户管理员、园区运营一类角色）。外部人员登录与自助改资料属于外部身份卷，本切片不提供入口。

## 4. 数据项

### 4.1 新表 `uq_enterprise_contact`

表名沿用库序对原联系人表的改名结论。无物理外键。

| 逻辑名 | 列名 | 类型意图 | 必填 | 规则 |
| --- | --- | --- | --- | --- |
| 主键 | `id` | Long | 是 | 与平台主键惯例一致 |
| 租户 | `tenant_id` | 字符串 | 是 | 与所属企业相同；查询必须带租户 |
| 企业 | `enterprise_id` | Long | 是 | 指向 `uq_enterprise.id`。企业须存在、未逻辑删除、且属本租户 |
| 姓名 | `contact_name` | 字符串 ≤64 | 是 | 去掉首尾空格后不得为空 |
| 电话 | `contact_phone` | 字符串 ≤32 | 否 | 允许数字、`+`、`-`、空格，以覆盖手机和座机。去掉空格后长度为 5–32；空串按空保存 |
| 角色 | `contact_role` | 字符串 ≤32 | 是 | 字典类型见 §4.3。默认 `OTHER` |
| 主联系人 | `is_primary` | 0 / 1 | 是 | 同一租户、同一企业、未删除行中至多一条为 1 |
| 备注 | `remark` | 字符串 ≤200 | 否 | 短备注 |
| 审计列 | 框架惯例 | — | 是 | 与平台一致 |
| 逻辑删除 | `del_flag` | 框架惯例 | 是 | 删除只改标志 |

源卷未给出、本草稿不建列的项：邮箱、证件号、即时通讯号、部门、排序号、职务自由文本。角色用字典表达，不再平行做一条职务字段。

### 4.2 回写冻结主档（不新增列）

主联系人变化时，只更新该企业的：

- `contact_name`
- `contact_phone`

不改名称、信用代码、位置、面积、入驻状态、备注。草稿默认同时更新企业的修改人与修改时间，使列表「更新时间」能反映联系人变更。若盒内同步改为「展示字段更新、审计时间不动」，实现时只改这一处，数据项不变。

没有主联系人行时，主档两个字段保持冻结稿行为，可由档案表单直接编辑。

### 4.3 角色字典

| 项 | 口径 |
| --- | --- |
| 字典类型 | `uq_enterprise_contact_role` |
| 草稿取值 | `LIAISON` 联络、`ADMIN` 行政、`FINANCE` 财务、`OTHER` 其他 |
| 与主标志的关系 | 角色不是主联系人标志。财务角色也可以是主联系人 |

参考档没有附联系人角色枚举。上表是草稿起点，G2 前可以改标签和编码，类型名锁定，以免和种子分叉。种子行归 S3（`UQ-DB-090`）。S3 未落库前，界面与接口使用同一组常量。不得改写 `uq_enterprise_settle_status`。

历史数据：上线时不批量生成联系人行。列表继续显示主档原值，直到用户生成或新建主联系人。

## 5. 操作路径

### 5.1 打开

1. 用户在企业列表点击某一行的「联系人」。
2. 前端带该行 `enterpriseId` 请求联系人分页。
3. 校验失败时按 §3 显示不可操作态。

### 5.2 子列表

- 必须分页，页大小跟随平台默认。
- 排序：主联系人在前，其余按修改时间倒序；修改时间相同则按主键倒序。
- 列：姓名、电话、角色、是否主联系人、更新时间、操作（查看 / 编辑 / 删除）。
- 备注放在查看态，不占主列。
- 无数据时提示新建。主档姓名非空且当前没有主联系人时，同时显示「从主档生成主联系人」。

### 5.3 新建

1. 在抽屉内打开空表单。姓名必填，角色默认「其他」。
2. 该企业没有任何未删除联系人时，本条保存为 `is_primary=1`，并回写主档。
3. 已有联系人时，默认不是主联系人。用户勾选「设为主联系人」后，原主联系人改为 0，本条为 1，并回写主档。
4. 标志位更新与主档回写在同一事务。失败则全部回滚。
5. 成功后留在该企业抽屉并刷新子列表。

### 5.4 编辑

可改姓名、电话、角色、备注、是否主联系人。不可改 `enterprise_id`。把联系人挪到另一家企业不在本切片。

当前唯一的主联系人不能直接改成非主。界面阻止保存，并提示先指定另一位主联系人。这样主档不会失去回写来源。

改为新的主联系人时，原主联系人降为非主，主档按新行回写。同一事务。

### 5.5 查看

只读展示 §4.1 的业务字段和审计信息。

### 5.6 删除

只做逻辑删除。一次提交的多条 id 必须属于同一企业，否则整批拒绝，提示「只能删除同一企业的联系人」。

删除非主联系人时，只改该行删除标志。

删除主联系人时先二次确认，确认文案写明列表上的联系人姓名会随之变化。确认后：

- 若还有其他未删除联系人：按 §5.2 的排序取下一条升为主联系人，回写主档。
- 若没有剩余：主档 `contact_name`、`contact_phone` 置空。

升主、回写、删除标志在同一事务。

### 5.7 从主档生成

显示与可调用条件：主档 `contact_name` 去掉首尾空格后非空，且该企业没有未删除的主联系人。

动作：插入一行，姓名和电话复制主档当前值，角色 `OTHER`，`is_primary=1`。不改主档内容。

已有主联系人时不插入，返回「已有主联系人」。重复点击不产生第二行。已有主联系人被用户改过姓名或电话时，本操作不可用，避免覆盖。

### 5.8 档案表单并存

冻结稿的档案新建/编辑仍保留「主联系人姓名 / 手机」。本切片不删这两个输入。

- 该企业没有主联系人行：表单只改主档，行为与冻结稿相同。
- 已有主联系人行：保存档案时，若姓名或电话与主联系人行不一致，以本次表单为准更新该主联系人行的姓名和电话。角色和主标志不动。同一事务。
- 档案表单不自动插入联系人行。插入只走 §5.3 或 §5.7。

## 6. 接口与权限

前缀保持 `/uq/site/enterprise`。响应包装、分页参数、错误码形态与平台一致。本切片不引入支付类幂等键；表单防重复提交即可。生成主联系人以「已有则不插入」作为幂等。

| 方法 | 路径 | 说明 | 权限 |
| --- | --- | --- | --- |
| GET | `/uq/site/enterprise/contact/list` | `enterpriseId` 必填，加分页参数 | `site:enterprise:contact:list` |
| GET | `/uq/site/enterprise/contact/{id}` | 详情；校验租户与企业 | `site:enterprise:contact:query` |
| POST | `/uq/site/enterprise/contact` | 新建；body 含 `enterpriseId` | `site:enterprise:contact:add` |
| PUT | `/uq/site/enterprise/contact` | 编辑；body 含 `id`。传入的 `enterpriseId` 与库内不一致则拒绝 | `site:enterprise:contact:edit` |
| DELETE | `/uq/site/enterprise/contact/{ids}` | 逻辑删除 | `site:enterprise:contact:remove` |
| POST | `/uq/site/enterprise/contact/bootstrap` | body 只有 `enterpriseId` | `site:enterprise:contact:add` |

业务规则失败（主联系人冲突、跨企业批量删除、生成条件不满足）返回明确提示，不用 500 代替。

菜单不新增一级目录。在现有企业档案菜单下增加按钮：联系人、联系人查询、联系人新增、联系人修改、联系人删除。`menu_id` 由菜单种子卷排号，本稿不指定数字。

数据范围只做租户隔离，不按部门再拆联系人。若企业主档以后补上数据权限，联系人跟随 `enterprise_id` 过滤，不单独做一套范围模型。

## 7. 验收

| # | 项 | 通过标准 |
| --- | --- | --- |
| C1 | 入口 | 同时具备企业查询与联系人列表权限的用户，从列表行打开抽屉，只看到该企业的联系人 |
| C2 | 隔离 | 其他租户或已删除企业的 id，列表为空或按「不存在」处理，不返回行 |
| C3 | 新建 | 缺姓名不能保存；成功后出现在子列表 |
| C4 | 首条即主 | 企业尚无联系人时，新建自动成为主联系人，主档姓名、电话与该行一致，企业列表联系人列同步 |
| C5 | 更换主联系人 | 更换后未删除行里只有一条主联系人；主档与企业列表同步为新行 |
| C6 | 禁止悬空 | 不能把唯一主联系人改成非主 |
| C7 | 删除 | 删除主联系人后，有剩余则下一条升主并回写；无剩余则主档姓名、电话为空。非主删除不影响主档 |
| C8 | 生成 | 条件满足时生成恰好一行；已有主联系人时再次调用不插入 |
| C9 | 档案并存 | 已有主联系人时，在档案表单修改姓名或电话，子表主联系人行同步；无主联系人行时不插入 |
| C10 | 权限 | 无对应权限则按钮不可见，接口 403。仅有列表权限时不能新建 |
| C11 | 前缀与结构 | 接口在 `/uq/site/enterprise/contact/**`；新表为 `uq_enterprise_contact`；`uq_enterprise` 不新增列；`sys_*` 不改结构 |
| C12 | 边界 | 无合同、工单、账单、空间树、外部登录入口。企业列表的筛选、分页、档案必填和入驻状态仍按冻结稿通过 |

本地验证记录须写明下一节点（B3 种子或 B4 工单），不以联系人冒烟代替 N2 编码收口。N2 编码在本草稿评审期间保持 HOLD。
