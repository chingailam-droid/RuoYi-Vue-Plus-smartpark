## 1. 职责与非职责

### 1.1 本切片做什么

S2 在 N2 企业主档之外，提供**按企业挂接的多名联系人**：可标角色、可启停、可指定至多一名主联系人，并把主联系人回写到主档上已有的扁化展示列。所属企业在新建时确定，编辑时锁定。

「扩展」在本卷只指两件事：联系人从主档扁化列提升为独立表；残余扩展属性不得再藏已经提升出去的企业挂接和角色。不新增第二张业务表。

### 1.2 本切片不做什么

- 不改 `uq_enterprise` 的入驻三态，不引入审批流。
- 不在编辑中更换所属企业。
- 不实现员工、部门、工牌、服务包、访客、资讯、门户聚合。
- 不把联系人做成外部登录身份。
- 不导出、不批量删除。
- 默认不做逻辑删除。
- 不在本卷写字典种子、菜单号段、接口详设、可执行 DDL。
- 不推动 N2 编码。

### 1.3 与 UQ-MOD-101 的边界

| 维度 | N2 · UQ-MOD-101 | S2 · 本卷 |
| --- | --- | --- |
| 主对象 | `Enterprise` / `uq_enterprise` | `EnterpriseContact` / `uq_enterprise_contact` |
| 联系人形态 | 主档两列：姓名、手机 | 独立多行；主档两列保留 |
| 角色 | 无 | 可空的角色码，字典在 S3 |
| 启停 | 无联系人状态 | `ACTIVE` / `INACTIVE` |
| 主联系人 | 两列即主联系人展示 | `is_primary=1` 的那一行与两列同步 |
| 入驻 | `PENDING` / `IN_PARK` / `LEFT`，编辑直改 | 联系人接口不以入驻态做门禁（§8 Q3） |
| 挂接 | — | 新建选定企业；编辑锁定 `enterprise_id` |

状态取值：`纳入` 本切片要有；`不做（默认）` 本切片不开放；`延后` 另刀；`不做` 明确排除。页面细则（列顺序、抽屉宽度、遮罩）以 SCR-ENT-03 为准，下表只锁能力。与 SCR 冲突时以本表 R4 为准。

| ID | 功能点 | 状态 | 模块口径 |

## 3. 状态

### 3.1 启停

联系人启停不走流程。接口不以企业入驻态做门禁。

```text
ACTIVE（启用） ──编辑──► INACTIVE（停用）
        ▲                    │
        └────────编辑────────┘
```

| 码 | 中文 | 页面标签意图 | 默认 |
| --- | --- | --- | --- |
| `ACTIVE` | 启用 | 成功色 | 新建默认 |
| `INACTIVE` | 停用 | 次要 / 默认色 | 无 |

停用后记录仍可查询、可再启用。停用不是删除。

### 3.2 主联系人

| 规则 | 口径 |
| --- | --- |
| 存储 | `is_primary`：`1` 是，`0` 否；默认否 |
| 唯一 | 每个企业至多一条主联系人；只统计 `del_flag=0`；靠应用层，不靠库唯一索引，也不靠手机号唯一 |
| 并发 | 两人同时把不同行设为主联系人时，后写不得留下两条未删除的 `1`；失败时接口返回明确文案 |
| 同号 | 允许同一企业多行手机号相同，页面不因重复手机拦截 |

### 3.3 与 N2 扁化列同步

主档 `uq_enterprise.contact_name` / `contact_phone` 继续存在，供 N2 列表展示。同步由保存联系人的服务完成，页面只提交主标记，不直接改主档其它字段。

| 动作 | 扁化列 |
| --- | --- |
| 将某行设为 `is_primary=1` | 同企其它未删除行的主标记清为 `0`；扁化姓名、手机改写成该行的姓名、手机（手机可空则扁化手机为空） |
| 主联系人行修改姓名或手机 | 扁化列跟随该行 |
| 更换主联系人 | 扁化列改指向新的主行 |
| 取消主标记，或停用当前主联系人 | **保留快照，不自动清空** |

### 3.4 角色

角色可空。非空时只能是五码之一：`LEGAL`（法人）、`FINANCE`（财务）、`IT`、`ADMIN`（行政）、`HR`。字典类型名 `uq_enterprise_contact_role`，数据与菜单同属 S3（UQ-DB-090 / UQ-DB-091）。本卷不写字典项正文，不锁菜单 id。

不设「每企每角色只能一人」。

### 3.5 扩展属性边界

联系人上的残余扩展只保留尚未提升为列的内容。企业挂接只用 `enterprise_id`，角色只用 `contact_role`。二者不得再写入扩展属性。

`biz_id` 与 `ext_json` 可以留在库表。二者不进新建、编辑、查看表单。

### 3.6 所属企业（编辑锁定）

新建时 `enterprise_id` 必填，企业须存在。一经保存，编辑态锁定：

- 表单中所属企业只读，不可改。
- 编辑接口禁止换企。请求里的 `enterprise_id` 与库中原值不一致时，拒绝且不落库。
- 本切片不提供换企。换企路径是删旧行再新建；逻辑删除不是本切片默认能力，该路径下一切片再开。

筛选条件里的「所属企业」只用于查询，不改行上的挂接。

| UC-4 | 编辑 | 所属企业只读。可改姓名、手机、角色、启停、主标记、备注。提交后列表、详情、主档扁化列按 §3.3 一致 | 请求改 `enterprise_id`：拒绝且不落库。校验失败留在抽屉并展示后端文案 |
| UC-5 | 查看 | 行内详情打开只读，所属企业不可改 | 记录已不存在则提示 |
| UC-6 | 启停 | 编辑中把启用改为停用或相反 | 不触发审批；不删行。若停用的是主联系人，扁化列保留快照 |
| UC-7 | 换企 | 本切片无此操作 | 不在编辑里换企。删旧+新建留到下一切片；本切片默认无逻辑删除 |

验收顺序（仍非编码令）：列表与四类筛选可用 → 新建可选企业、编辑企业只读 → 同企未删除主联系人只有一条且扁化列按 §3.3 跟随或保留快照 → 无权限被挡住。接口契约另刀，不在本卷假装已经有 UQ-API-102。
